# 创作者体验执行任务清单（优先于 DevEx）

## 背景与目标

- 当前阶段优先级：先解决创作者用户体验，开发者体验仅保持不阻塞。
- 主链路：`项目 -> 剧本 -> 美术 -> 分镜 -> 评审预览集`。
- 本轮目标：让新用户在 30 分钟内拿到第一份可分享评审预览集，并在失败时可恢复。

## North Star 与验收口径

- **North Star**：更快出片（评审预览集先于最终成片导出）。
- **主验收指标**
  - `TTFV`（登录到首次生成评审预览集）<= 30 分钟
  - 主链路 5 步完成率可观测
  - 每步 Top3 阻塞原因可观测
  - 失败重试成功率可观测

## P0 / P1 / P2 任务清单

## P0（必须先做，阻塞交付）

- [x] **T1（P0）固定 5 步主链路进度条**
  - 目标：用户始终知道当前在哪一步、下一步是什么。
  - 范围：`项目/剧本/美术/分镜/评审预览集` 五段常驻展示。
  - 验收：
    - 登录后进入 Studio 即可见 5 步进度条。
    - 每一步状态至少支持：`未开始/进行中/已完成/阻塞`。

- [x] **T2（P0）每步单一主 CTA（下一步）**（Studio 底栏「下一步」+ 原有步骤内 CTA 仍保留，后续可再收敛）
  - 目标：减少决策负担，避免在“更多”或多个工作台中迷路。
  - 范围：每步只保留 1 个主按钮，次要动作下沉。
  - 验收：
    - 任一步骤可直接通过主 CTA推进。
    - 不进入“更多”也可完成主链路推进。

- [x] **T3（P0）评审预览集终点打通**
  - 目标：主链路必须有可分享、可评审的交付物。
  - 范围：第 5 步提供“生成评审预览集”并可打开。
  - 验收：
    - 能生成可打开的预览页面/链接。
    - 页面可见镜头列表与基础预览信息。
  - **落地**：`/projects/:id/review-pack` 全屏壳 + `StudioReviewPackScope`（就绪汇总与分镜行）；交付步 `StudioMergeDeliverBar`「镜头评审列表」与进度条第 5 里程碑直达同一路由；支持复制链接与 AppBar 刷新。

- [x] **T4（P0）失败可恢复闭环**（Studio 主壳内最小闭环；全量可观测见 T7）
  - 目标：失败不会中断流程，用户可自助恢复。
  - 范围：关键失败点提供`原因 + 下一步建议 + 重试/继续`。
  - 验收：
    - 人工制造失败后，用户可一键重试并继续流程。
    - 错误文案为用户语言，不暴露内部实现术语。
  - **落地**：`failedJobCount > 0` 时顶部可点条跳转任务中心；`StudioApiErrorCallout` 用户向文案 + 重试；评审预览页与项目 Studio 加载失败均可重试/刷新。

## P1（强烈建议同周期完成）

- [x] **T5（P1）信息架构降噪**（Studio 主壳最小版；模板见 T6）
  - 目标：主链路前置，工具能力后置。
  - 范围：`更多` 菜单重新分层，主链路入口固定可见。
  - 验收：
    - 新用户可在 1 屏内找到“下一步”。
    - 非主链路功能不抢主视觉焦点。
  - **落地**：五步条 + 底栏「下一步」为主视觉；「工作台」菜单分 **主链路 / 评审预览集 / 工作台工具** 三段，样式降为次要；资产/视频/质量不再与主链路步骤平铺。

- [x] **T6（P1）模板与预设（最小版本）**
  - 目标：降低从零开始成本，提升首日成功率。
  - 范围：先上线 1-2 个高频模板（剧情/镜头节奏）。
  - 验收：
    - 模板可一键应用并进入后续步骤。
    - 模板路径的 TTFV 优于手动路径。
  - **落地**：后端 `starter_creator_plot` / `starter_creator_shot_rhythm`；剧本步 `CreatorStarterTemplatesStrip` 主按钮「一键应用」+ `launch_intent` 跳步/Agent；`starter_apply` 遥测。

- [x] **T7（P1）主链路状态可观测**（客户端埋点 + 后端 audit 聚合报表）
  - 目标：能定位“用户为什么卡住”。
  - 范围：埋点五步状态、阻塞原因、重试结果。
  - 验收：
    - 可产出 Top3 阻塞原因报告。
    - 可看见每步完成率和重试成功率。
  - **落地**：`CreatorJourneyTelemetry`（`step_selected` / `next_cta` / `review_pack_*` / `failed_jobs_open_tasks`）；`bindProject` 批量 `POST …/creator-journey-events`（写入 `app_project_audit`，`action=creator_journey`）；`GET …/creator-journey-summary` 返回 Top 事件、步骤分布、`retry_event_count`；Debug `debugPrint` + `debugSink` 供测试。

## P2（可后置，但需排期）

- [x] **T8（P2）评审包协作增强**（团队反馈最小版；版本对比后置）
  - 目标：支持小团队工作室协作评审。
  - 范围：评论/审核状态/版本对比的最小能力。
  - 验收：
    - 评审包可被团队成员查看并给出反馈状态。
  - **落地**：`source=review_pack` 质量评审（后端校验扩展）；评审包每镜头 Chip + 菜单（通过/需改/标记）+ 可选备注；团队汇总条；复制链接供成员打开同一页。

- [x] **T9（P2）成片导出与评审包衔接**（评审包页最小桥接）
  - 目标：从评审通过到导出成片路径连贯。
  - 范围：在评审包成功后明确导出入口与前置检查。
  - 验收：
    - 用户能清楚看到“何时可导出、还缺什么”。
  - **落地**：`StudioReviewPackExportBridge` 拉取 `short-video-export-check`，展示可导出/阻塞文案、Top 阻塞项与 CTA（可导出→`deliver?tab=publish`，未就绪→`deliver?tab=assembly`）；`review_pack_open_deliver` 遥测。

## 4 周执行节奏

- **Week 1**：完成 T1 + T2（主链路可见化与单 CTA）
- **Week 2**：完成 T3（评审预览集终点）
- **Week 3**：完成 T4 + T7（失败恢复 + 可观测）
- **Week 4**：完成 T5 + T6（IA 降噪 + 模板加速）

> 说明：T8/T9 进入后续里程碑，不阻塞当前“30 分钟评审包”目标。

## 每周验收截图点位

- [x] Studio 首页可见 5 步进度条
- [x] 任一步阻塞态（含可操作建议）（进度条 blocked 态 + 失败任务条跳转任务中心）
- [x] 评审预览集生成中进度反馈（加载文案 + 指示器）
- [x] 评审预览集成功页（含镜头列表）
- [x] 失败后重试并恢复成功（`StudioApiErrorCallout` 重试 + 评审页刷新；widget 测试覆盖失败条）

## 非目标（本阶段不做）

- 不以“最终成片导出”作为首个必须成功的唯一终点（先评审包）。
- 不做大规模 DevEx 工程改造（只做不阻塞交付的最小保障）。
- 不做多平台一次性铺开（先把当前主路径做到稳）。
