# 全栈交付约定（任务计划与合并门禁）

**适用范围**：`docs/plans/` 下一切 **竖切任务清单**（`tasks-*.md`）、**路线图分册**（`roadmap-*.md`）中的 **工作包（WP）**、以及 [**`workspace-team-full-plan.md`**](./workspace-team-full-plan.md) 等 **平台级计划**。  
**目标**：避免「**只合后端、前端仍断**」或「**OpenAPI 变了但 `rust_api`/屏幕未改**」进入主线。

---

## 1. 默认规则（除非该 WP 明确标为 **ops-only**）

| 能力是否对用户/运营可见？ | **Rust `backend/`** | **OpenAPI + WS 文档**（若涉及） | **`frontend/` Flutter**（含 `rust_api`、工作台 UI、错误提示） |
|---------------------------|---------------------|-----------------------------------|------------------------------------------------------------------|
| **是**（REST/WS/队列结果影响产品路径） | **必做** | **必做** | **必做** |
| **否**（纯日志、纯 DB 批处理、纯运维脚本，无 API 面） | **必做** | 不适用则跳过 | **可标 ops-only**：在任务清单该节首行写 `**交付范围：ops-only（无 Flutter）**` 并说明原因 |

**合并定义**：同一能力若分多 PR，**最后一笔合并到默认分支的 PR** 须已满足上表；禁止长期留下「后端已上、前端仍调旧路径」的窗口期（超过 **1 个发布周期** 须开 issue 标为 **debt**）。

---

## 2. 验收与门禁

- **必跑**：`yarn refactor:check`（含 `flutter analyze` / `flutter test` 与 OpenAPI / `rust_api` 一致性，见仓库根 [`AGENTS.md`](../../AGENTS.md)）。
- **用户路径**：凡新 REST，至少一条 **Flutter 主路径** 或 **契约/widget 测试** 证明客户端已接；仅 smoke 无 UI 的，须在任务文档写明 **「首屏入口计划」** 与目标日期。

---

## 3. 与「平台级」关系

平台级能力除功能 parity 外，常包含 **可发现性**（设置里能配）、**可观测**（错误码对用户可读）、**可运营**（内部或管理视图）。**仅后端 JSON 不算平台交付**——须在计划文档中写清 Flutter/运营面归属（可指向 [**`platform-capabilities-backlog.md`**](./platform-capabilities-backlog.md) 中的条目）。
