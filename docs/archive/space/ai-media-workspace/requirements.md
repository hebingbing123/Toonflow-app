# 需求文档：AI Media Workspace

## 概述

AI Media Workspace 是 Openflow 面向 **视频生产、图片素材处理、AI 工作流编排** 的统一产品空间。

本 Space 采用 **桌面生产优先、Web / 手机协作优先、Rust Core 统一、Flutter UI 统一** 的策略，不追求把完整重型剪辑器塞进浏览器，也不把所有重媒体计算默认压到中心服务端。

当前目录落点已经确定为仓库根目录同级的 [`../../rust_core/`](../../rust_core/README.md) workspace，而不是继续把编辑内核塞在 `backend/` 子树里。

## 需求 1：平台分工必须明确

### 1.1 桌面端是主生产工作台

桌面端必须承载以下重型能力：

- 视频时间线编辑
- 图片素材精修
- 本地代理生成
- 高质量预览
- 本地或混合导出
- 高强度 AI 工作流编排

### 1.2 Web / 手机端是协作与任务入口

Web / 手机端默认承担：

- 项目查看
- 素材上传
- 参数配置
- 评论与审核
- 任务发起
- 进度查看
- 结果回看

### 1.3 重型编辑操作要引导到桌面端

当用户在 Web / 手机端触发以下操作时，系统必须给出桌面端接力路径，而不是假装支持：

- 多轨时间线编辑
- 高频预览拖动
- 大批量素材精修
- 高质量导出
- 本地模型重计算

## 需求 2：Flutter 是统一 UI 壳

### 2.1 统一产品表面

桌面、Web、手机端都应共享统一的工作台语言：

- 项目
- 工作流
- 任务
- 资产
- 评论
- 发布

### 2.2 能力门禁可以不同

虽然 UI 语言统一，但各端可见能力必须按平台受限：

- 桌面端展示完整编辑入口
- Web / 手机端展示协作入口与桌面接力提示

## 需求 3：Rust Core 是统一编辑与工作流内核

### 3.1 Rust Core 负责的能力

Rust Core 必须统一承载：

- 视频时间线模型
- 图片图层 / 蒙版 / 变换模型
- 媒体探针
- 代理生成
- 字幕 / 旁白 / BGM 编排
- AI 任务调度
- 导出队列
- 项目持久化模型

### 3.2 Rust Core 必须支持两种宿主形态

同一套 Rust Core 应尽量支持：

1. **桌面嵌入式宿主**
2. **服务端宿主**

两者共享核心数据结构和业务规则，但运行资源与能力开关可以不同。

## 需求 4：图片编辑不绑定 Photoshop

### 4.1 产品目标

图片编辑能力要服务于 Openflow 的素材生产，而不是追求 PSD 全兼容。

### 4.2 首期应支持

- 图层
- 遮罩
- 裁切
- 旋转 / 缩放 / 平移
- 文字与标注
- 基础滤镜
- AI 抠图 / 扩图 / 重绘
- 批量导出

### 4.3 首期不承诺

- PSD 高保真往返
- Photoshop 调整层全兼容
- RAW / CMYK / 印刷级完整流程
- 大型画笔生态与插件生态

## 需求 5：视频编辑以 AI 工作流和粗剪为先

### 5.1 首期应支持

- 镜头顺序管理
- 候选视频切换
- 启停镜头
- 字幕与旁白编排
- BGM 管理
- 代理预览
- 批量导出
- AI 辅助粗剪

### 5.2 后续增强方向

- 更完整的时间线视图
- 转场与节奏处理
- 多轨语音 / BGM / 字幕管理
- 版本对比

### 5.3 首期不追求

- 电影工业级 NLE
- 重度调色合成系统
- 无上限自由轨道编辑器

## 需求 6：Web / 手机到桌面的接力必须顺滑

### 6.1 项目上下文接力

用户在 Web / 手机端创建或编辑的项目，桌面端登录后必须能直接恢复：

- 当前项目
- 当前脚本 / 分镜
- 当前任务上下文
- 当前素材选择
- 当前工作流参数

### 6.2 下载引导

当用户命中桌面专属能力时，系统应支持：

- 桌面端下载引导
- 登录后自动打开对应项目
- 可选 deep link / 二维码 / 邀请链接接力

### 6.3 不允许的糟糕体验

- 只提示“请去桌面端”但不告诉用户怎么继续
- 切到桌面后找不到原来的项目上下文
- 桌面端需要重复上传或重复配置

## 需求 7：服务端主要负责协作、调度和可选云任务

### 7.1 默认职责

Rust 服务默认承担：

- 项目与权限
- 协作与评论
- 任务状态管理
- AI 调度
- 结果回写
- 轻量预览元数据
- 可选批量渲染任务

### 7.2 默认不承担

默认不把以下能力作为中心服务端主链路：

- 所有用户的实时重预览
- 所有用户的本地级粗剪反馈
- 所有导出的唯一执行入口

### 7.3 可选云端能力

当业务需要时，可独立启用：

- 夜间批量出片
- 云端 Whisper / 视频理解
- 云端 ComfyUI / Runway / 生成式视频流水线
- 团队共享渲染农场

## 需求 8：AI 工作流必须是第一等能力

### 8.1 工作流类型

系统应支持以下 AI 工作流节点或等价阶段：

- 转录
- 静音检测
- 场景检测
- 图片生成 / 修图
- 视频生成 / 补帧 / 变体
- 字幕生成
- 文案生成
- 批量导出

### 8.2 编排要求

工作流应支持：

- DAG 或等价可追踪依赖关系
- 重试
- 取消
- 进度
- 结果回写
- 阶段级失败原因

## 需求 9：项目与资产模型必须跨端统一

### 9.1 同一项目模型

视频、图片、字幕、旁白、工作流、任务，都必须属于同一项目上下文，而不是分裂成多个平行系统。

### 9.2 资产模型统一

系统必须统一表达：

- 原始素材
- 代理文件
- 派生图
- 派生视频
- 预览图
- 导出物

### 9.3 本地缓存与云端引用并存

桌面端应允许本地缓存大文件与代理；服务端保存项目引用、状态和需要同步的衍生物。

## 需求 10：成本边界必须内建进产品设计

### 10.1 默认走桌面生产

产品默认路径必须优先利用用户本地算力，而不是隐性把所有成本转嫁给平台。

### 10.2 云端使用应可解释

凡是需要云端执行的任务，应能回答：

- 为什么必须上云
- 是否可排队
- 是否可按需购买
- 是否可由桌面端本地完成

## 需求 11：验收必须分波次完成

### 11.1 波次 A：协作入口与桌面接力

- Web / 手机端协作面
- 桌面下载引导
- 项目接力打开

### 11.2 波次 B：图片素材编辑 MVP

- 基础图层与蒙版
- AI 素材处理
- 批量导出

### 11.3 波次 C：视频粗剪与导出 MVP

- 时间线装配
- 代理预览
- 字幕 / 旁白 / BGM
- 批量出片

### 11.4 波次 D：AI 工作流深化

- ComfyUI / Whisper / 外部 API 编排
- 任务回写与质量门禁

### 11.5 波次 E：可选云端渲染与团队运营

- 团队批量渲染
- 夜间任务
- 更强的运营与审计视图
