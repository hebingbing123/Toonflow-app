# 1. 背景

当前重构分支已经完成 Rust + Flutter + Harness 主体迁移，但“能跑”不等于“能稳定产出高质量短剧”。接下来进入“功能优先下的完善阶段”：

1. 先补齐仍影响业务闭环的功能缺口。
2. 在不牺牲视频质量的前提下压缩大模型 token 成本。
3. 评估并增强自动化记忆能力，让人物风格、情绪、镜头连续性、失败经验能跨轮复用。
4. 目标不是“更像 AI 工作流”，而是“用尽量少的 token 生成尽量自然、可信、稳定的短剧视频”。

本 spec 作为后续若干轮竖切优化的真源，优先级高于临时口头偏好。

# 2. 明确约束

## 2.1 产品约束

- 项目尚未上线，默认可以直接修改当前实现，无需为旧行为保留额外兼容层。
- 若“省 token”与“提升视频质量”冲突，优先视频质量。
- 每轮只跑与改动直接相关的检查；暂不为单次小改执行全量门禁。
- 等功能与质量优化阶段基本收束后，再统一执行一次全量检查与回归。
- 每轮优化完成后都要再 review 一次：当前方向是否仍有必要继续深挖，若收益下降则转向下一个高 ROI 点。

## 2.2 质量底线

生成结果至少要同时满足：

- 角色风格稳定，不一镜一张脸，不出现明显“AI 漂移”。
- 情绪表达自然，不是机械朗读式表演。
- 镜头、动作、环境、音色存在层次变化，不是全程一个状态。
- 避免明显穿帮：服装、空间、道具、光线、运动逻辑不应无故跳变。
- 失败经验能被吸收，下次同类镜头不重复犯错。

# 3. 现状 review 结论

基于当前仓库，系统并非“没有记忆”，而是“已有记忆基础，但还需要产品化收敛”。

## 3.1 已有能力

- 已有通用 agent memory：
  - `backend/src/settings/agent_memory/`
  - 支持 `style_bible` / `stage_summary` / `delta_memory` / `message`
  - 已有按 `owner_user_id + numeric_project_id + agent_type + episodes_id + scope_signature` 的隔离维度（这里的 `numeric_project_id` 是当前记忆子系统内部隔离键，不代表产品级 project scope 语义应回退为 numeric-first）
- 已有项目级自动记忆预算策略：
  - `backend/src/settings/agent_memory/policy.rs`
  - 已支持 `off / lean / standard`
  - 已能判定低价值记忆、做预算快照和优化
- 已有视频提示词专用记忆：
  - `backend/src/production/workbench/video_prompt_memory/`
  - 已覆盖 selected / rejected / observation / style / continuity / role 等方向
- 已有“按镜头风险决定记忆预算”的测试与实现：
  - `backend/src/production/workbench/meta/generate/tests/build_prompt_core.rs`
- 已有若干质量属性测试：
  - 情绪渐进
  - 景别连续
  - 低信号观察剔除
  - 自动负向约束可追踪

## 3.2 当前主要缺口

现阶段更像“模块已存在”，但仍缺少统一的业务闭环：

1. 缺少一份把“功能补齐、质量提升、token 压缩、自动记忆”串成同一执行路线的 spec。
2. 记忆能力偏工程内聚，离“用户可感知的生成质量收益”还缺一层策略编排。
3. “何时该多花 token，何时该极致压缩”已有局部规则，但还缺跨流程统一预算。
4. 自动记忆虽然存在，但还缺更明确的独立性约束、淘汰规则、收益评估与触发时机。
5. 质量 review、失败归因、后续 prompt 修正之间仍可继续闭环。

# 4. 核心决策

## 4.1 采用“增强现有记忆体系”，不新建平行系统

本阶段不再另造一套“Codex 风格自动记忆平台”，而是在现有 `agent_memory + video_prompt_memory` 上增强自动写入、检索压缩、收益追踪、隔离治理。

理由：

- 当前仓库已经有项目级、脚本级、角色级、负向经验级记忆基础。
- 重新造平行系统会引入重复写入、竞争策略和更高 token 成本。
- 现有结构已具备隔离字段，适合直接补齐“自动化”和“预算治理”。

## 4.2 采用“质量优先、分层省 token”而非统一瘦身

不是所有镜头都压 token。应按风险和收益分层：

- 低风险镜头：lean memory + 精简 prompt
- 高风险镜头：expanded budget + 更强约束 + 更完整上下文
- 连续失败镜头：直接进入归因/补丁模式，而不是一味重试

## 4.3 自动记忆必须严格隔离

自动记忆只能在以下范围内生效：

- 同一用户
- 同一项目
- 同一 agent 类型
- 同一剧集/脚本范围（如适用）
- 同一角色 / 镜头 / scope signature（如适用）

禁止把 A 用户 / A 项目总结出的风格或失败经验污染到 B 用户 / B 项目。

# 5. 目标状态

## 5.1 功能目标

1. 先 review 当前工作流还有哪些缺失功能会直接拉低出片质量。
2. 缺什么补什么，优先补业务闭环里真正缺失的能力。
3. 功能收束后，再持续优化生成链路质量与 token ROI。

## 5.2 质量目标

1. 人物风格更稳。
2. 情绪与表演更自然。
3. 视频更真实，不像模板化 AI 合成。
4. 失败镜头能被系统吸收为后续约束。
5. 同项目逐步形成“项目自己的表达风格”。

## 5.3 成本目标

1. 高风险镜头允许花 token。
2. 低风险镜头尽量复用已有结构化记忆、少传低价值上下文。
3. 自动记忆要有预算上限、淘汰策略、低价值过滤，避免“质量只涨一点，成本烧太多”。

# 6. 记忆策略设计

## 6.1 记忆分层

沿用并强化现有分层：

- `style_bible`
  - 项目级稳定设定
  - 角色锚点、风格禁忌、视觉母题
  - 高价值，保留优先级最高
- `stage_summary`
  - 阶段完成态、关键导演决策、当前主要风险
  - 用于减少重复把整段工作流历史喂给模型
- `delta_memory`
  - 局部修正、连续性补丁、某类镜头的临时注意事项
  - 必须带 scope，避免污染全局
- `rejected / observation / selected video prompt memories`
  - 作为视频生成专用的正反样本记忆
  - 强化“哪些表达有效、哪些容易翻车”

## 6.2 自动记忆写入原则

仅在以下场景自动写入：

1. 明确提升后续镜头质量的稳定风格信息。
2. 明确降低穿帮或人物漂移风险的约束。
3. 明确来自坏例复盘的失败经验。
4. 明确可复用的情绪 / 表演 / 镜头调度模式。

以下内容默认不写入或优先淘汰：

- 空泛总结
- 低信号赞美语
- 与当前项目无关的泛化表达
- 无 scope 的临时修正
- 重复已有结论的近义废话

## 6.3 自动记忆独立性

记忆主键范围至少包含：

- `owner_user_id`
- `numeric_project_id`
- `agent_type`
- `episodes_id` 或等价阶段范围
- `scope_signature`

后续若引入“项目风格自学习”，也必须继续落在上述隔离边界内，不能做跨租户共享记忆。

# 7. Token 优化策略

## 7.1 优化原则

- 优先减少“重复、低信号、可由结构化字段替代”的上下文。
- 不减少“维持人物稳定、情绪自然、镜头真实”所需的高价值上下文。
- 能用记忆摘要表达的，不重复塞整段历史对话。
- 能靠负向约束避免的失败，不用反复靠重试烧 token。

## 7.2 优先优化对象

1. 重复传输的导演手册碎片
2. 重复角色设定文本
3. 重复场景/道具锚点
4. 低信号 observation note
5. 缺少剪枝的 rejected memory
6. 阶段推进里可被 `stage_summary` 替代的长历史

## 7.3 预算模式

- `lean`
  - 低风险镜头
  - 只注入必要锚点、必要负向约束、必要连续性
- `standard`
  - 默认模式
  - 平衡质量与成本
- `expanded`
  - 高风险镜头、情绪戏、人物特写、连续失败镜头
  - 允许更完整上下文

后续应把“何时进入 expanded”从局部函数继续提升为更明确的工作流规则。

# 8. 功能完善优先级

## 8.1 第一优先：补业务闭环缺口

先 review 当前生产流程，补足会直接影响成片质量的缺功能，例如：

- 质量 review 到记忆回写是否还有断点
- 坏例归因是否足够结构化
- 是否缺少对“情绪/表演/角色稳定性”的显式反馈入口
- 是否缺少能让用户确认“这是项目风格锚点”的轻量操作
- 是否缺少对失败镜头的局部返工路径

## 8.2 第二优先：提高短剧质量

在功能闭环补齐后，重点提高：

- 角色连续性
- 情绪曲线
- 台词表演自然度
- 镜头变化层次
- 光影/动作/环境一致性
- 坏例复发率下降

## 8.3 第三优先：压缩 token 成本

在质量不回退的前提下：

- 剪掉冗余 prompt
- 提高结构化上下文占比
- 提高记忆复用率
- 降低重复失败重试成本

# 9. 分阶段实施

## Phase A: Workflow Gap Review

目标：找出“当前还缺什么功能，不补就会直接拖累质量”。

交付：

- 当前业务流程缺口清单
- 每个缺口对质量/成本的影响评级
- 决定先补哪条竖切

## Phase B: Quality Loop Closure

目标：打通“生成 -> review -> 归因 -> 回写约束 -> 下次生成”的闭环。

交付：

- 坏例分类更稳定
- 失败经验可转为自动负向约束或项目记忆
- 局部返工路径优先处理高风险镜头

## Phase C: Memory Governance

目标：把自动记忆从“有模块”提升为“可控、可压缩、可评估”的系统。

交付：

- 自动写入准入规则
- 低价值记忆淘汰
- 预算超标清理
- 项目级自动记忆模式更清晰
- 记忆独立性审计

## Phase D: Token ROI Optimization

目标：在质量不退化前提下减少平均上下文体积。

交付：

- 高低风险镜头预算分流
- 长上下文替换为阶段摘要
- 低信号 observation / rejected note 剪枝
- 可量化的 token 与质量对照数据

## Phase E: Missing Feature Completion

若前述优化完成后现有功能已基本无缺口，则继续补“应有但尚缺失”的能力。

候选方向：

- 更明确的角色风格锚点管理
- 更轻量的项目风格确认流程
- 更直接的坏例回放与修复入口
- 更细粒度的镜头风险分级

# 10. 验收标准

满足以下条件才算这一轮“完善阶段”真正有效：

1. 至少一个关键业务闭环缺口被补齐。
2. 视频质量优化不是停留在 prompt 文案层，而是能通过记忆、约束、review 或返工机制稳定复用。
3. 自动记忆未破坏租户 / 项目 / 剧集隔离。
4. token 优化有明确边界，未以牺牲出片质量为代价。
5. 每轮优化后都有一次继续 review，确认下一个最高收益点。

# 11. 测试与验证策略

按当前阶段约束执行：

- 单次修改只跑对应模块的最小必要测试。
- 不在本 spec 阶段要求每次都跑仓库全量门禁。
- 全量 `refactor-check` 留到本轮功能与质量优化阶段接近收束后统一执行。

建议优先采用：

- 目标模块单测 / 属性测试
- 单一路径契约测试
- 针对高风险提示词构建逻辑的回归样本
- 记忆隔离与压缩规则测试

# 12. 本 spec 对应的首批执行建议

建议按以下顺序推进：

1. 先做一次 workflow gap review，确认当前还缺哪些质量相关功能。
2. 先补“质量闭环缺口”而不是先做纯 token 优化。
3. 之后收紧自动记忆治理与预算治理。
4. 再做 token ROI 压缩。
5. 每完成一轮，重新 review 是否还有更高收益缺口需要切换方向。
