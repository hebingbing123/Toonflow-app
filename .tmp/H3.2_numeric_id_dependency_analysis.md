**Task**: 确认 Flutter `rust_api` 与主路径 UI 不再依赖待删列

## Executive Summary

The migration from `project_numeric_id` to `project_uuid` has made **significant progress** in the Flutter UI layer. This update removes **all unused `projectNumericId` parameters** from the `storyboard_editor` and `script_editor` widget signatures, completing the UUID-first migration for these components.

**Key Achievement**: The `storyboard_editor` and `script_editor` now operate entirely on UUID-first patterns, with no widget state referencing `projectNumericId`.

However, **backend removal of numeric ID columns remains blocked** due to:

1. **Import/Export Infrastructure**: `promote_import_snapshots()` function is tightly coupled to numeric IDs for conflict resolution
2. **Production API Contracts**: `rust_api/production/**` endpoints still accept `projectId` (numeric) as a legacy parameter
3. **Job Payload Compatibility**: Worker processes and job visibility logic still parse `project_numeric_id` from payloads
4. **Contract Tests**: `pg_contract_tests` suite validates numeric ID behavior

### 3. Backend Dependencies

#### 3.1 Import/Export Infrastructure

**Status**: 🔴 **CRITICAL BLOCKER** - Cannot remove numeric columns

**File**: `supabase/migrations/20260420120000_rename_legacy_staging_to_import_staging.sql`

The `promote_import_snapshots()` function performs idempotent upserts from `import_staging.snapshot` (JSONB payloads from SQLite export) into `app_*` tables. It relies heavily on numeric IDs for conflict resolution:

```sql
-- Projects: Uses numeric_id as primary key for conflict resolution
INSERT INTO public.app_project (numeric_id, name, ...)
SELECT (s.payload ->> 'id')::integer, ...
FROM import_staging.snapshot s
WHERE s.source_table = 'o_project'
ON CONFLICT (numeric_id) DO UPDATE ...

-- Scripts: Joins to projects via numeric_id and stores numeric_project_id
INSERT INTO public.app_script (project_id, numeric_id, numeric_project_id, ...)
SELECT p.id, (s.payload ->> 'id')::integer, ...
FROM import_staging.snapshot s
INNER JOIN public.app_project p 
  ON p.numeric_id = NULLIF(s.payload ->> 'projectId', '')::integer
...

-- Storyboards: Similar pattern with numeric joins and metadata preservation
INSERT INTO public.app_storyboard (script_id, numeric_id, numeric_script_id, numeric_project_id, ...)
SELECT sc.id, (s.payload ->> 'id')::integer, ...
FROM import_staging.snapshot s
INNER JOIN public.app_script sc ON sc.numeric_id = NULLIF(s.payload ->> 'scriptId', '')::integer
...
```

**Critical Dependencies**:
- `app_project.numeric_id` - Used as conflict resolution key and join target
- `app_script.numeric_id` - Used for conflict resolution
- `app_script.numeric_project_id` - Used for metadata preservation and joins
- `app_storyboard.numeric_id` - Used for conflict resolution
- `app_storyboard.numeric_project_id` - Used for metadata preservation
- `app_storyboard.numeric_script_id` - Used for joining during import
- All other `numeric_id` columns across tables - Used for ON CONFLICT clauses

**Removal Blockers**:
1. Historical import data in `import_staging.snapshot` uses numeric IDs as primary keys
2. No UUID-based import path exists
3. Contract test `promote_staging_populates_assets_and_links` validates this flow
4. Function has `SECURITY DEFINER` and `service_role` permissions - critical for data integrity

## Blockers for Column Removal

### Critical Blockers

1. **Import Infrastructure** (Priority: HIGH)
   - `promote_import_snapshots()` function must be rewritten to use UUIDs

   - Alternative: Keep import columns but mark as deprecated, create UUID-only import path

2. **Job Payload Backward Compatibility** (Priority: MEDIUM)
   - Existing job records with `project_numeric_id` in payload

   - Alternative: Backfill job payloads with `project_uuid`, deprecate numeric parsing

3. **Contract Test Coverage** (Priority: MEDIUM)
   - Tests validate numeric ID import flow
   - Alternative: Add UUID-based import tests, mark numeric tests as legacy

### Non-Blocking Dependencies

1. **Production API Contracts** (Priority: LOW)
   - `rust_api/production` endpoints accept numeric IDs but prefer UUIDs
   - Can be deprecated via OpenAPI annotations
   - Frontend already migrated to UUID-first

2. **Notification Payloads** (Priority: LOW)
   - Notifications include `projectNumericId` for backward compat
   - Can be removed once all clients upgraded

   - Add OpenAPI `deprecated: true` to `projectId` parameters
   - Update documentation to recommend UUID-only usage
