## Policy Document Analysis

### Core Permission Matrix from `workspace-project-permission-policy.md`

**Default Workspace-Level Permissions:**
- `owner` / `admin`: Can delete any project in the workspace
- `member`: Can create projects, can only delete their own projects
- `owner`: Can invite members, manage members, manage billing, delete workspace
- `admin`: Can invite members, manage members, delete any project (but NOT manage billing or delete workspace)
- `member`: Can create projects (but NOT invite members, manage members, or delete others' projects)

**Special Rules:**
- Workspace must always have at least one owner
- Last owner cannot be demoted or removed
- When member is removed, their `current_workspace_id` resets to personal workspace
- When workspace is archived, all members' `current_workspace_id` resets to personal workspace
