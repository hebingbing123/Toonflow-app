### 2. Safe Backfill Migration: Job Payload `project_uuid`

#### 2.1 Migration Goal
Enrich existing `app_generation_job` payloads to include `project_uuid` when:
- Payload contains `project_numeric_id`
- Payload does NOT contain `project_uuid`
- The project still exists in `app_project`

#### 2.2 Safety Analysis
**✅ SAFE** because:
1. **Additive only** - adds data, does not remove anything
2. **Idempotent** - can be run multiple times safely
3. **Non-breaking** - backend code already handles both UUID and numeric
4. **No schema changes** - only updates JSONB payload content
5. **Preserves existing data** - does not overwrite existing `project_uuid`

**⚠️ Considerations**:
1. **Performance** - may need to run in batches for large datasets
2. **Orphaned jobs** - jobs referencing deleted projects will be skipped
3. **Archived projects** - should still backfill (jobs remain visible to owner)

#### 2.3 Migration Implementation

```sql
-- Backfill project_uuid into app_generation_job payloads
-- Safe additive migration: enriches existing data without removing anything
-- Related: H3.5 (platform-completion-phase2), D-batch HTTP API convergence

-- This migration backfills project_uuid into job payloads that have project_numeric_id
-- but are missing project_uuid. This prepares for eventual removal of numeric_id columns
-- (D-batch) while maintaining backward compatibility during the transition period.

DO $$
DECLARE
  v_updated_count INTEGER := 0;
  v_batch_size INTEGER := 1000;
  v_total_candidates INTEGER;
  v_batch_num INTEGER := 0;
BEGIN
  -- Count total candidates for backfill
  SELECT COUNT(*)
  INTO v_total_candidates
  FROM public.app_generation_job j
  WHERE j.payload ? 'project_numeric_id'
    AND NOT (j.payload ? 'project_uuid');
  
  RAISE NOTICE 'Starting backfill: % jobs need project_uuid enrichment', v_total_candidates;
  
  -- Process in batches to avoid long-running transactions
  LOOP
    WITH batch AS (
      SELECT j.id, j.payload, p.id AS project_uuid
      FROM public.app_generation_job j
      INNER JOIN public.app_project p 
        ON p.numeric_id = (j.payload->>'project_numeric_id')::integer
      WHERE j.payload ? 'project_numeric_id'
        AND NOT (j.payload ? 'project_uuid')
      LIMIT v_batch_size
    )
    UPDATE public.app_generation_job j
    SET 
      payload = jsonb_set(
        j.payload,
        '{project_uuid}',
        to_jsonb(batch.project_uuid::text)
      ),
      updated_at = NOW()
    FROM batch
    WHERE j.id = batch.id;
    
    GET DIAGNOSTICS v_updated_count = ROW_COUNT;
    
    EXIT WHEN v_updated_count = 0;
    
    v_batch_num := v_batch_num + 1;
    RAISE NOTICE 'Batch %: Updated % job payloads', v_batch_num, v_updated_count;
    
    -- Small delay between batches to reduce load
    PERFORM pg_sleep(0.1);
  END LOOP;
  
  -- Report final statistics
  SELECT COUNT(*)
  INTO v_total_candidates
  FROM public.app_generation_job j
  WHERE j.payload ? 'project_numeric_id'
    AND NOT (j.payload ? 'project_uuid');
  
  RAISE NOTICE 'Backfill complete: % jobs still missing project_uuid (orphaned or deleted projects)', v_total_candidates;
  
  -- Verify backfill coverage
  DECLARE
    v_total_with_project INTEGER;
    v_with_uuid INTEGER;
    v_coverage_pct NUMERIC;
  BEGIN
    SELECT 
      COUNT(*) FILTER (WHERE payload ? 'project_numeric_id' OR payload ? 'project_uuid'),
      COUNT(*) FILTER (WHERE payload ? 'project_uuid')
    INTO v_total_with_project, v_with_uuid
    FROM public.app_generation_job;
    
    IF v_total_with_project > 0 THEN
      v_coverage_pct := (v_with_uuid * 100.0) / v_total_with_project;
      RAISE NOTICE 'Coverage: %.2f%% of project-scoped jobs now have project_uuid', v_coverage_pct;
    END IF;
  END;
END $$;

-- Add comment documenting the backfill
COMMENT ON TABLE public.app_generation_job IS 
  'Async generation jobs; Rust API uses service user via JWT sub. Payload backfilled with project_uuid (H3.5) to prepare for D-batch numeric_id column removal.';
```
