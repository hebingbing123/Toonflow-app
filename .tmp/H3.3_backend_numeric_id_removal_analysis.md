# H3.3 Backend Numeric ID Removal Analysis

**Task**: 从 `backend/src/` 移除仅服务 legacy 列的 handler 或查询分支（随 D 清单逐项执行）  
**Date**: 2025-01-27

## Executive Summary

After comprehensive analysis of `backend/src/`, **no handlers or query branches were found that exclusively serve legacy numeric ID columns without UUID-based equivalent paths**.

All current backend handlers follow the **UUID-first, numeric fallback** pattern, which is the correct migration strategy. Removing these fallback paths would break compatibility with:
1. Existing job payloads containing `project_numeric_id`
2. Import infrastructure (`promote_import_snapshots()`)
3. Contract tests validating numeric ID behavior

## Analysis Methodology

### 1. Grep Analysis
Searched for:
- `project_numeric_id` usage patterns
- `numeric_id` usage patterns
- Handlers with `i32` project_id parameters
- Path parameters using numeric IDs exclusively

### 2. Code Review
Examined:
- `backend/src/jobs/handlers/` - All job listing and summary endpoints
- `backend/src/production/` - All production workbench handlers
- `backend/src/assets/` - Asset workbench handlers
- `backend/src/narrative/` - Novel, event, and storyboard handlers

```rust
// From backend/src/jobs/handlers/common.rs
pub(crate) fn workspace_visibility_clause() -> &'static str {
    r#"
        (
            app_generation_job.owner_user_id = $1
            OR EXISTS (
                SELECT 1
                FROM app_project p
                INNER JOIN app_workspace_member wm ON wm.workspace_id = p.workspace_id
                WHERE wm.user_id = $1
                  AND (
                    (app_generation_job.payload->>'project_uuid' IS NOT NULL
                     AND p.id::text = app_generation_job.payload->>'project_uuid')
                    OR
                    (app_generation_job.payload->>'project_numeric_id' IS NOT NULL
                     AND (app_generation_job.payload->>'project_numeric_id') ~ '^[0-9]+$'
                     AND p.numeric_id = (app_generation_job.payload->>'project_numeric_id')::int)
                  )
                  AND p.archived_at IS NULL
            )
        )
    "#
}
```

**Removal Blockers**:
- Existing job records with `project_numeric_id` in payload
- Worker processes still extract numeric IDs from payloads
- Job visibility queries need to support both for backward compatibility

## Critical Blockers for Column Removal

### 2. Job Payload Compatibility (HIGH)

### 3. Contract Tests (MEDIUM)

### 4. Harness WS Context (MEDIUM)
- `HarnessContext` contains `project_legacy_id` / `script_legacy_id`
- Harness tools in `backend/src/harness/invoke/domain_*.rs` use numeric IDs
- WS attach protocol needs to be updated to support UUID-first

## Recommendations

### Phase 1: Preparation (No Breaking Changes)
1. **Create UUID-based Import Path**
   - Add `promote_import_snapshots_v2()` function using UUID-based joins
   - Migrate `import_staging.snapshot` to include `project_uuid` in payloads
   - Run both functions in parallel during transition

2. **Backfill Job Payloads**
   - Add migration to populate `project_uuid` in existing job payloads where missing
   - Update job enqueue paths to always include both UUID and numeric (dual-write)

3. **Deprecate Numeric-Only Paths**
   - Add OpenAPI `deprecated: true` to numeric-only parameters (if any exist)
   - Update documentation to recommend UUID-only usage

### Phase 2: Deprecation (Soft Removal)
1. **Mark Columns as Deprecated**
   - Add database comments indicating deprecation
   - Update RLS policies to prefer UUID-based checks
   - Monitor usage via database logs

2. **Remove Numeric Parsing from New Code**
   - New endpoints should reject numeric-only requests
   - Existing endpoints log warnings when numeric IDs used without UUID

### Phase 3: Hard Removal (Breaking Change)
**Prerequisites**:
- All job payloads backfilled with UUIDs
- Import function migrated to UUID-based logic
- Contract tests updated
- DBA approval for column removal

**Steps**:
1. Drop `promote_import_snapshots()` (old version)
2. Rename `promote_import_snapshots_v2()` to `promote_import_snapshots()`
3. Create migration to drop numeric ID columns
4. Update contract tests to use UUID-only paths
5. Remove numeric ID parsing from job/worker code

**Estimated Timeline**: 2-3 release cycles (6-9 months)
