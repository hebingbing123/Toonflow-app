## 技术实现 / Technical Implementation

### 1. 辅助函数设计

所有新函数都遵循现有的 `validate_non_empty_string`、`validate_range`、`validate_enum` 模式：

```rust
use crate::error::locale::{current_locale, ApiLocale};

pub fn bad_request_i18n(en_msg: &str, zh_msg: &str) -> ApiError {
    let msg = match current_locale() {
        ApiLocale::En => en_msg,
        ApiLocale::Zh => zh_msg,
    };
    ApiError::BadRequest(msg.to_string())
}
```

### 2. 语言偏好机制

- 通过 `Accept-Language` 请求头传递语言偏好
- 支持 `q=` 权重参数（如 `zh-CN;q=0.9, en;q=0.8`）
- 使用 `tokio::task_local!` 存储当前请求的语言偏好
- 默认回退到英文

### 3. 测试覆盖

所有新函数都包含以下测试：
- 基本功能测试（验证逻辑正确）
- 英文环境测试（默认行为）
- 中文环境测试（使用 `REQUEST_LOCALE.scope(ApiLocale::Zh, ...)` 模拟）

## 使用示例 / Usage Examples

### Before (仅英文):
```rust
if body.id <= 0 {
    return Err(ApiError::BadRequest("id must be positive".into()));
}

if !is_member {
    return Err(ApiError::Forbidden("not a workspace member".into()));
}
```

### After (双语):
```rust

validate_positive(body.id, "id")?;

if !is_member {
    return Err(forbidden_i18n(
        "not a workspace member",
        "不是工作空间成员"
    ));
}
```
