# C1.8 内容合规 WebSocket 推送全双工测试实现总结

## 任务概述

为内容合规通知系统添加专用的 WebSocket 推送全双工自动化集成测试，验证当内容合规设置变化时，WebSocket 通知能够正确实时推送。

## 实现内容

### 1. 新增全双工 WebSocket 测试

**文件**: `backend/src/app/pg_contract_tests/ops_suite/content_compliance_ws_push_roundtrip.rs`

**测试函数**: `content_compliance_ws_full_duplex`

**测试覆盖场景**:

1. **创建新告警的 WebSocket 推送**
   - 订阅 `WsNotifyHub` 接收通知
   - 调用 `/api/v1/settings/notifications/content-compliance/sync` 创建告警
   - 验证收到 `settings.notification.created` WebSocket 消息
   - 验证消息格式和内容（`notificationType`、`title`、`message`、`linkPath`、`payload`）

2. **更新已有告警的 WebSocket 推送**
   - 同步更新后的告警数据
   - 验证收到 `settings.notification.updated` WebSocket 消息
   - 验证 count 字段更新正确
   - 验证 `readAt` 被重置为 null

3. **告警消退的 WebSocket 推送**
   - 同步空告警列表（表示所有告警已消退）
   - 验证收到 `content_compliance_alert_cleared` 通知
   - 考虑节流策略可能跳过的情况

4. **多个告警同时推送**
   - 同步包含多个告警的列表
   - 验证每个告警都收到独立的 WebSocket 消息
   - 验证所有告警的 stage 都被正确推送

### 2. 测试执行脚本

**文件**: `scripts/run_content_compliance_ws_tests.sh`

提供便捷的测试执行脚本，自动加载环境变量并运行所有内容合规 WebSocket 测试。

**使用方法**:


**前置条件**:

- 数据库已执行所有迁移
- 契约测试用户种子已存在（`aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa`）

## 技术实现细节

### WebSocket 测试架构

测试使用 `tokio::sync::mpsc::unbounded_channel` 创建消息通道：
- 通过 `WsNotifyHub::subscribe()` 订阅用户的 WebSocket 通知
- 使用 `tokio::time::timeout` 等待 WebSocket 消息
- 验证消息的 JSON 格式和字段内容
- 测试结束后通过 `WsNotifyHub::unsubscribe()` 清理订阅

### 与现有测试的互补关系

- **现有测试** (`content_compliance_ws_push_create_update_cleared` 等)：
  - 验证数据库状态正确性
  - 验证 REST API 响应正确性
  - 通过存储层函数签名间接验证 WebSocket 推送

- **新增测试** (`content_compliance_ws_full_duplex`)：
  - 直接验证 WebSocket 消息的实时推送
  - 验证消息格式和内容的完整性
  - 验证全双工通信流程

## 注意事项

1. 测试需要本地 PostgreSQL 数据库和 Supabase JWT secret
2. 数据库需要包含所有必要的迁移和表结构
3. 需要契约测试用户种子数据
4. 测试会自动清理创建的通知数据
5. WebSocket 消息接收使用 2 秒超时，足够本地测试使用
