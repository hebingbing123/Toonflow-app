# 需求文档：short-video-space

## 概述

把 Toonflow 已有的项目、小说、剧本、分镜、资产、任务、质量评审和 Agent 工作区，收敛成面向短视频生产的上层入口。重点不是重做底层生产域，而是：

1. **借鉴开源已验证流程**：参考 `MoneyPrinterTurbo`（单入口、集中参数、成片导向）与 `Jellyfish`（准备态、readiness、候选确认、任务回跳、结果回写），迁入现有 Rust + Flutter + Postgres 工作流，不照搬技术栈或单体任务目录模型。
2. **补上分发环**：在生成与导出之后增加可选自动发布（国内与海外平台），与半自动发布并存；自动发布独立于生成任务，属于 `export` 之后的独立流程。

文档真源：`space/short-video/README.md`、`implementation-breakdown.md`、`auto-publishing-platforms.md`、`open-source-borrowing.md`、`docs/plans/moneyprinter-short-video-space.md`（MoneyPrinter 优点迁移与 **MP-Wave** 语义）。

## 文档与 Wave 编号对读（重要）

仓库里存在**两套 Wave 口径**，本 spec 区分书写：

| 口径 | 来源 | 含义（摘要） |
|------|------|----------------|
| **MP-W1…MP-W7** | `moneyprinter-short-video-space.md` | MP-W1 = Space **入口编排**（动漫/真人、项目写回、跳转、标准路径）；MP-W2 = 统一视频目标与批量候选成片等；MP-W3～MP-W7 = Jellyfish 风格准备态、媒体沉淀、任务调度台、成片装配、低优剪辑。 |
| **impl Wave 1…6** | `implementation-breakdown.md` | impl Wave 1 = **项目级短视频目标配置**（多字段持久化）；impl Wave 2 = readiness/候选；impl Wave 3 = 成片装配与导出检查；impl Wave 4～6 = 发布与回流等。 |

**当前约定**：**MP-W1（入口编排）正在实现**，本 spec **不为 MP-W1 追加新的实现任务条目**（避免与进行中的工作重复）；与 MP-W1 重叠的验收以该计划文档与主分支为准。**impl Wave 1（全量项目级配置）**与 **MP-W2** 在「统一视频目标配置」上高度重叠，任务在 `tasks.md` 的 **B 节**跟踪（不等同于 MP-W1）。

### 术语：「创作目标配置」与需求 5.2a（避免与 MP-W1 混淆）

- 文中「创作目标配置」指 **impl Wave 1 / MP-W2 向** 的项目生产参数，**非** MP-W1 入口编排单独一波。
- 需求 **5.2a** 的 `publish_profiles` 是**分发默认值**（标题风格、标签策略等），与上述「生产侧目标配置」并列，勿混用「Wave 1」简称。

## 核心约束

- 产品表述稳妥：**支持多平台发布自动化，可按平台能力选择自动发布或半自动发布**；不承诺所有平台一开始即全自动。
- 不优先做重型时间线剪辑器、多轨精细后期；成片以 rough cut 与导出前检查为先。
- 配置与状态尽量项目级收口，避免散落在单次任务参数中。
- 架构落点：Rust `backend/` 配置与任务编排与发布作业；Flutter `frontend/` Space 编排；数据库记录发布配置、排程、状态、审计；Harness/Agent 用于多平台文案与诊断。

## 需求 1：短视频 Space 产品分段与入口

### 1.1 四段能力模型

1. **选题与目标配置**：题材、模式、画幅、平台、时长、创作手册。
2. **生产编排**：脚本、素材、分镜、旁白、字幕、成片装配。
3. **质检与回写**：就绪态、坏例、返工、版本确认。
4. **分发与复投**：平台映射、发布排程、文案改写、发布结果回流。

其中前三段主要复用现有 Toonflow 能力；第四段为本线特色增量。

### 1.2 Space 作为项目级总入口

- Space 首页应能表达「当前项目卡在哪一环」，并统一跳转 Script Workspace、Production Workspace、任务中心、质量评审。
- **第一屏显式模式**（`moneyprinter-short-video-space.md`）：`动漫短剧` 与 `真人短剧` 二选一（或等价 UI），共用同一生产主链、前置准备与验收重点可区分。
- 借鉴 `MoneyPrinterTurbo` 的「从主题到成片的顺序式入口」与「下一步可见」，而非其单体 Python MVC 或单任务目录式输出。

### 1.3 可见主链与「下一步」（开源单入口流水线）

- 在 Space 层展示**线性主链**（与 MPT 任务链精神一致，UI 表述随产品定稿）：脚本 → 素材/分镜准备 → 旁白/字幕 → 成片装配 → 导出 → 发布准备；每一步可显示完成/阻塞与深链到对应工作台。
- **下一步**：根据 readiness、导出检查、发布准备结果计算「建议用户处理的单一或 Top-3 动作」，避免用户自行判断「该打开哪个台子」。

### 1.4 项目生产概览（open-source-borrowing P0 + moneyprinter MP-W5）

- **项目级生产概览**：一屏汇总当前项目在生成、导出、发布各段的进度与阻塞（与「卡在哪一环」互补，偏数据汇总而非仅阶段枚举）。
- **建议指标**（`moneyprinter-short-video-space.md` MP-W5）：已就绪分镜数、生成中任务数、待复核坏例数（与质量评审域对接，字段以现有表为准）。
- **阶段语义**（Jellyfish）：`shot preparation` → `candidate confirmation` → `ready for generation` → `export ready` 在 Toonflow 中映射为可读阶段或标签，供概览与主链使用（不要求与 Jellyfish 同名代码结构）。

## 需求 2：项目级短视频目标配置（impl Wave 1 / MP-W2 / P0）

### 2.1 后端

- 项目短视频配置读写模型；后续脚本、制作、导出、发布接口均能读取同一套配置。
- 支持字段（与实施文档对齐）：`mode`（动漫 / 真人）、`video_ratio`、`target_market`、`target_platforms`、`duration_strategy`、`voice_profile`、`subtitle_style`、`bgm_strategy`。
- 数据：优先挂在现有项目扩展字段，不强制首轮拆新表。

### 2.2 前端

- 在短视频 Space 增加正式的项目级目标配置面板。
- 配置完成后展示「当前创作模式摘要」与「当前默认发布市场 / 平台」。

### 2.3 验收

- 用户在 Space 内完成配置且刷新后保留；子流程读取同一套项目级配置。

## 需求 3：分镜 readiness 与候选确认（Wave 2 / P0）

### 3.1 后端

- 分镜 `readiness summary` 聚合接口；**最小检查项**（与 `implementation-breakdown` 对齐）：基础信息是否齐、提示词/脚本上下文是否齐、参考图或关键帧是否齐、候选角色/场景/道具是否确认完成、当前是否已有进行中任务。
- **扩展检查项**（与 `open-source-borrowing` 中 Jellyfish 核对清单对齐，按 Toonflow 字段可映射则纳入，不可映射则记为「缺口/后续」）：语义默认值是否齐、`action beats` 是否齐、待确认候选是否清空、视频 prompt 是否可渲染、默认模型与 provider 是否可用等。
- 候选资产正式状态：`pending`、`linked`、`ignored`。

### 3.2 前端

- 项目级 readiness 摘要；分镜工作区展示「未就绪原因」；候选确认摘要卡（信息不散落在多角落）。

### 3.3 验收

- 用户能直接看到「为何不能批量生成」并能从摘要跳到需处理的分镜或资产。

### 3.4 统一资产总览（候选 + 已确认）

- **资产工作台或 Space 内嵌总览**：已确认资产与候选资产同视图展示（借鉴 Jellyfish `shot_assets_overview` / `shot_extracted_candidates` 思路）；候选操作驱动 `pending | linked | ignored`。
- readiness 计算**应依赖**候选确认是否完成（与开源文档一致：未清空候选则不应视为「可批量生成」就绪）。

## 需求 4：成片装配与导出前检查（Wave 3 / P0）

### 4.1 后端

- 成片装配域读写；统一读取已选视频、旁白文案/音频、字幕源、BGM 配置。
- 导出前检查：缺视频、缺字幕、缺旁白、时长异常、当前版本是否已确认等。

### 4.2 前端与任务

- Space 内「成片装配」入口；按剧本顺序查看成片缺失项；导出前检查摘要。
- 导出类任务失败时给出缺字段/缺素材/缺当前版本等可行动原因，并能回跳到项目与剧本。

### 4.3 导出前质量检查钩子（open-source-borrowing P1）

- 在「导出前检查」之上，可选接入现有**质量门控/质量评审**结论（例如未通过关键门槛时导出警告或阻断——具体策略实现期再定）；本需求只要求 **spec 层预留钩子与展示位**，避免与质检域脱节。

### 4.4 验收

- 用户可在不进入复杂剪辑台的情况下完成首版导出；系统明确提示导出阻塞项。

## 需求 5：发布域与发布准备（Wave 4 / P0–P1）

### 5.1 产品

- 将 Space 从「生产台」扩展为「生产 + 分发」工作台；发布为 export 之后独立流程（见 `auto-publishing-platforms.md`）。

### 5.2 后端数据模型（最小建议）

- `publish_profiles`、`publish_drafts`、`publish_targets`、`publish_jobs`、`publish_attempts`。

### 5.2a 发布目标配置（`publish_profiles` / 项目发布偏好，与 `auto-publishing-platforms` 对齐）

- 项目级或可复用 profile 级维护：**目标市场**（国内 / 海外 / 双端）、**默认平台集合**、**默认标题风格**、**默认标签策略**、**默认简介模板**、**默认发布时间策略**（与 Wave 1「创作目标配置」区分：后者偏生产参数，前者偏分发默认值）。

### 5.2b 成片发布单（`publish_drafts` 字段清单）

- 每条待发布视频一张 draft，至少覆盖：`来源项目`、`来源剧本/分镜/成片`、`视频文件`、`封面`、`标题`、`简介`、`标签`、**平台差异化文案**（可嵌套或关联子表）、`发布时间`、`发布状态`、与 `publish_targets` / `publish_jobs` 的关联。

### 5.3 发布准备检查

- 比例/时长是否符合平台要求；标题长度；封面；标签；平台必填字段等。

### 5.4 发布任务状态机

建议状态：`queued`、`validating`、`uploading`、`platform_processing`、`succeeded`、`partial_failed`、`failed`、`retrying`；任务可回跳到发布单与项目。

### 5.5 前端

- 发布准备面板；发布单列表；平台状态视图；用户可知哪些平台可自动发、哪些仅半自动。

### 5.6 半自动发布与人工确认

- 对标注为「半自动」或高风控平台：`validating` 通过后进入**用户确认**再 `uploading`；API 与 UI 需支持「准备完成 → 用户确认 → 投递」而非默认一键全平台发出（与 `auto-publishing-platforms` 边界一致）。

### 5.7 验收

- 用户可从成片进入发布准备；平台能力分层表述清晰；半自动路径有明确确认点。

## 需求 6：多平台文案、排程与结果回流（Wave 5–6 / P1–P2）

### 6.1 多平台文案改写（Wave 5）

- Agent 生成平台差异化：标题、简介、标签、发布时间建议；`platform adapter` 负责字段映射与约束校验。
- 前端：发布单中展示国内版/海外版/平台版文案；支持立即发布与定时发布；同一成片多平台排程。

### 6.2 发布结果回流（Wave 6）

- 回写：平台视频 id、发布链接、发布时间、失败原因、重试历史；后续可扩播放、点赞、评论、完播率。
- **发布结果审计**：对每次尝试保留结构化记录（对应 `publish_attempts`），支持按项目/草稿/平台查询与排障（`auto-publishing-platforms` Wave 4 明确提及「发布结果审计」）。
- 前端：项目级发布概览；按平台查看成功/失败/待重试。

### 6.2a 表现数据扩展（P2 / 可选波次）

- 同步或拉取：播放量、点赞、评论、完播率；**低表现预警**作为后续增量（`auto-publishing-platforms` 特色 D 后续能力），本 spec 在 Wave 6 仅要求**数据模型或占位接口**以免返工。

### 6.3 验收

- 同一成片可生成多套平台文案且用户可改后再投递；发布结果回到项目上下文，失败可回到发布单修复。

## 需求 7：自动发布平台分层与首批接入

### 7.1 平台分层（第一层）

- **国内**：抖音、哔哩哔哩、小红书、视频号、快手。
- **海外**：TikTok、YouTube Shorts、Instagram Reels、Facebook Reels。

### 7.2 接入优先级（第二层）

- 优先：有开放 API 或较稳定发布方式、支持上传与元数据的基础模型。
- 后做：权限与资质门槛高、强依赖人工二次确认的平台。

### 7.3 推荐首批代表平台（实施文档倾向）

- 海外：YouTube Shorts、TikTok。
- 国内：哔哩哔哩、抖音。

用于验证「竖屏短视频 + 创作者工作流」与产品价值。

## 需求 8：特色能力与不做清单

### 8.1 特色能力

- **一次生成，多平台改写**（同成片多套标题/简介/标签）。
- **发布前合规检查**（画幅、时长、标题、封面、标签、必填字段）。
- **定时与批量发布**（立即/定时、多平台串行、日历批量排程）。
- **发布结果回流**（链接、id、失败与重试）。

### 8.2 当前阶段不建议优先做

- 重型时间线剪辑器、多轨精细后期。
- 一开始就承诺所有平台全自动发布。
- 先做平台数据分析大盘再补发布本体。

## 需求 11：任务中心与结果回路（Jellyfish 借鉴）

### 11.1 业务对象回跳

- 任务完成后**回写**业务上下文（生成/导出/发布相关字段由现有域承接，本 spec 要求发布与导出任务有明确回写契约）。
- 任务列表支持按对象深链：`project` / `script` / `storyboard` / `publish`（与 `open-source-borrowing` 一致）。

### 11.2 失败与重试体验

- 失败时不仅展示错误码：提供**返工入口**（重新生成、局部返工、回写补偿等——复用现有工作台能力，Space 或任务详情负责路由）。
- `publish` 与导出任务支持从任务详情跳回**发布单草稿**、**成片装配**或**分镜**。

### 11.3 任务中心过滤

- 支持按「短视频 Space 相关阶段」过滤或标签视图（生成 / 导出 / 发布），满足 `open-source-borrowing` P1。

## 需求 14：`moneyprinter-short-video-space.md` 规划增量（MP-Wave）

### 14.1 MP-W1：入口编排（**正在实现 — 本 spec 不追加实现任务**）

- 新增 `短视频 Space`；用户切换 **动漫短剧 / 真人短剧**；在 Space 内选择项目并将 `projectType=short_drama`、`mode`、`videoRatio` 等写回项目（以该计划文档与当前代码为准）。
- 从 Space 跳转：项目、脚本工作区、制作工作区、任务中心、质量评审；**明确一条标准路径**串联已有能力。
- 文档所述「第一阶段四件事」：项目入口收口、脚本入口收口、制作入口收口、结果入口收口（题材/风格/创作手册/目标平台等可在 MP-W1 与后续波次间切分，以主分支实现为准）。

### 14.2 MP-W2：MoneyPrinter 风格能力补齐（与 impl 项目级配置、任务编排重叠）

- **统一视频目标配置**：平台、画幅、时长、创作模式、语音、字幕样式、BGM（与需求 2 / impl Wave 1 对齐）。
- **一键批量生成候选成片**（依托现有 jobs；Space 发起与进度可见）。
- **旁白、字幕、BGM** 成为可追踪的**任务阶段**（类型或阶段标签，与需求 11 协同）。
- **成片候选可比对的质量验收摘要**（与质量评审/门控衔接）。

### 14.3 MP-W2 真人模式附加

- 真人参考图/参考镜头素材；角色与场景真实感约束；偏口播、表演、纪实感的脚本模板倾向；与动漫模式**不同的质量验收维度**。

### 14.4 MP-W3：生成前准备态（增强需求 3）

- 分镜更明确的 **`ready for generation` 视图状态**；Space **未就绪原因**归因到剧本、分镜、角色、参考图、视频参数等；候选确认流与 readiness 依赖（与需求 3.4 一致）。

### 14.5 MP-W4：生成结果沉淀为可复用资产

- **分镜媒体槽位**清晰：参考图、关键帧、当前生效视频、候选视频、导出结果分区管理。
- **设当前视频 / 局部返工 / 导出** 统一为分镜**媒体操作**语义，减少结果散落在任务与临时链接。
- **批量生成回写摘要**（哪些分镜已有可复用结果、哪些仅有任务无结果）；**回写失败 / 回写不完整**显式诊断（避免任务成功但分镜上下文未同步）。

### 14.6 MP-W5：任务中心作短视频调度台（增强需求 11、1.4）

- 任务中心 **project / script / storyboard** 快捷回跳（`publish` 见需求 11.1）。
- 视频、出图、导出等任务的**阶段标签**：素材准备、出图、出视频、导出成片、质检（与 H 节任务对齐）。
- 失败重试细分为：**重新生成**、**局部返工**、**回写补偿**（与需求 11.2 对齐）。

### 14.7 MP-W6：后期输出与成片装配（增强需求 4）

- 成片装配 rough cut；每分镜导出**最小字段**校验；按剧本/分镜顺序预组装批量成片输出。
- **导出结果质量摘要**：缺帧、字幕缺失、旁白缺失、时长异常、未选当前视频等（可与导出前检查合并实现，但验收维度独立）。
- **BGM、字幕样式、旁白声线** 收成**项目级或成片级**配置，避免逐分镜重复配置（与 `moneyprinter-short-video-space.md` 原文一致）。

### 14.8 MP-W7：低优先级后期剪辑

- 成片剪辑台只读版 → 镜头级基础重排/启停/替换当前视频版本 → 成片级字幕与 BGM 调整 → 导出前总校验 → 评估简单时间线 → 评估多轨/轻量轨道模型；**完整 NLE、多轨精细剪辑、帧级转场** 保持后置（同原文「暂不建议一开始就做」）。

## 需求 15：开源借鉴边界（非功能代码，约束设计）

- **不深借**：`MoneyPrinterTurbo` 的单体 MVC、以单视频任务为中心的状态、本地任务目录式输出；`Jellyfish` 的全栈照搬；脱离 Toonflow 项目/剧本/分镜模型的孤立 readiness。
- **深借**：Jellyfish 的 preparation → candidate confirmation → ready for generation 路径、readiness 聚合、任务与业务对象回跳、生成结果回写镜头/媒体上下文；MoneyPrinterTurbo 的单入口流水线感与集中参数、成片装配优先路径、快速批量候选成片（在 Toonflow 内由现有生成与任务体系承载，Space 负责编排与可见性）。
