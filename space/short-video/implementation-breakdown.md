# 短视频 Space 实施拆分

## 目的

这份文档把前面的两类结论进一步落成实施面：

- 开源项目中哪些能力值得借
- Toonflow 还缺哪一段分发与自动发布能力

目标不是再写一份抽象方案，而是把后续工作拆成可以进入实现的后端、前端、数据和任务项。

## 总体判断

短视频 Space 最合适的推进顺序不是“先做完整剪辑器”，而是：

1. 先把项目级短视频目标配置做实
2. 再把分镜 readiness 和候选确认做实
3. 再把成片装配和导出前检查做实
4. 最后补发布准备、发布任务和平台适配

这条顺序同时吸收：

- `MoneyPrinterTurbo` 的入口感和成片导向
- `Jellyfish` 的 preparation / readiness / task center 闭环

## Wave 1：项目级短视频目标配置

### 产品目标

让 Space 不只是“进入某个工作台的快捷入口”，而是项目级短视频总控台。

### 后端

- 给项目补短视频配置读写模型
- 支持保存：
  - `mode`: 动漫 / 真人
  - `video_ratio`
  - `target_market`
  - `target_platforms`
  - `duration_strategy`
  - `voice_profile`
  - `subtitle_style`
  - `bgm_strategy`
- 让后续脚本、制作、导出、发布接口都能读取这组配置

### 前端

- 在 `短视频 Space` 增加正式的项目级目标配置面板
- 配置完成后显示“当前创作模式摘要”
- 显示“当前默认发布市场 / 平台”

### 数据

建议先挂在现有项目扩展字段上，不急着一开始就拆新表。

### 验收

- 用户能在 Space 内完成配置，而不必跳去别处
- 配置能在刷新后保留
- 后续子流程读取的是同一套项目级配置

## Wave 2：分镜 readiness 与候选确认

### 产品目标

把“能不能生成”从用户主观判断，变成系统可解释状态。

### 后端

- 为分镜增加 `readiness summary` 聚合接口
- 明确 readiness 检查项：
  - 基础信息是否齐
  - 提示词/脚本上下文是否齐
  - 参考图或关键帧是否齐
  - 候选角色/场景/道具是否确认完成
  - 当前是否已有进行中任务
- 为候选资产增加正式状态：
  - `pending`
  - `linked`
  - `ignored`

### 前端

- 在 Space 中显示项目级 readiness 摘要
- 在分镜工作区显示“未就绪原因”
- 增加候选确认摘要卡，而不是把候选信息散落在多个角落

### 数据

- 如现有资产/分镜模型已能承载，优先沿用
- 若不够，再补候选状态或聚合读模型

### 验收

- 用户能直接看到“为什么当前项目还不能批量生成”
- 用户能从摘要直接跳到需要处理的分镜或资产

## Wave 3：成片装配与导出前检查

### 产品目标

先把“能稳定产出 rough cut”做出来，再考虑复杂编辑。

### 后端

- 增加成片装配域读写
- 统一读取：
  - 已选视频
  - 旁白文案 / 音频
  - 字幕源
  - BGM 配置
- 增加导出前检查：
  - 是否缺视频
  - 是否缺字幕
  - 是否缺旁白
  - 时长是否异常
  - 当前版本是否已确认

### 前端

- 在 Space 内新增“成片装配”入口
- 显示导出前检查摘要
- 支持按剧本顺序查看成片缺失项

### 任务

- 导出类任务应能回跳到项目和剧本
- 导出失败时应给出“缺字段 / 缺素材 / 缺当前版本”的具体原因

### 验收

- 用户可以在不进入复杂剪辑台的情况下完成首版导出
- 系统能明确提示导出阻塞项

## Wave 4：发布准备与自动发布基础版

### 产品目标

把短视频 Space 从生产台扩成“生产 + 分发”工作台。

### 后端

- 新增发布域模型
- 最小建议包括：
  - `publish_profiles`
  - `publish_drafts`
  - `publish_targets`
  - `publish_jobs`
  - `publish_attempts`
- 新增发布准备检查：
  - 比例是否符合平台要求
  - 时长是否符合平台要求
  - 标题长度是否超限
  - 是否缺封面
  - 是否缺标签
  - 是否缺平台必填字段

### 前端

- 在 Space 增加“发布准备”面板
- 增加发布单列表
- 增加平台状态视图

### 任务

新增 `publish` 任务类型，建议状态为：

- `queued`
- `validating`
- `uploading`
- `platform_processing`
- `succeeded`
- `partial_failed`
- `failed`
- `retrying`

### 验收

- 用户可以从成片直接进入发布准备
- 用户可以知道哪些平台能自动发，哪些只能半自动

## Wave 5：多平台文案改写与排程

### 产品目标

让自动发布不是“传同一份标题到所有平台”，而是平台适配后的分发。

### 后端

- Agent 生成平台差异化：
  - 标题
  - 简介
  - 标签
  - 发布时间建议
- 平台 adapter 负责字段映射和约束校验

### 前端

- 在发布单中显示“国内版 / 海外版 / 平台版”文案
- 支持立即发布和定时发布
- 支持一个成片多平台排程

### 验收

- 同一成片能生成多套平台文案
- 用户能修改后再投递

## Wave 6：发布结果回流与效果跟踪

### 产品目标

把发布结果纳入 Toonflow 上下文，而不是留在平台后台里。

### 后端

- 回写：
  - 平台视频 id
  - 发布链接
  - 发布时间
  - 失败原因
  - 重试历史
- 后续可扩：
  - 播放
  - 点赞
  - 评论
  - 完播率

### 前端

- 在 Space 中显示项目级发布概览
- 按平台查看成功/失败/待重试状态

### 验收

- 发布结果能回到项目上下文
- 用户能从失败结果回到发布单修复

## 建议的接口与模块落点

### Backend

优先新增或扩展：

- `short_video_space` 项目配置接口
- `storyboard readiness summary` 聚合接口
- `publish` 域路由与服务
- `publish adapter` 平台抽象层
- `publish jobs` worker

### Frontend

优先新增或扩展：

- `short_video_space` 配置面板
- readiness 摘要面板
- 候选确认摘要面板
- 成片装配入口
- 发布准备面板
- 发布单列表与状态视图

## 推荐优先级

P0：

- 项目级目标配置
- readiness 摘要
- 候选确认摘要
- 成片装配入口
- 发布准备状态

P1：

- 发布单模型
- 平台适配层
- `publish` 任务状态机
- 多平台文案改写

P2：

- 定时发布
- 批量排程
- 表现数据回流
- 轻量粗剪

## 不建议当前阶段先做的事

- 重型时间线剪辑器
- 多轨精细后期系统
- 一开始就承诺所有平台全自动发布
- 先做平台数据分析大盘，再补发布本身

## 下一步最适合进入代码的切口

如果只选一个最小可交付竖切，建议先做：

1. 项目级短视频目标配置
2. 分镜 readiness 摘要
3. 发布准备状态占位

因为这三件事一旦做出来，短视频 Space 就会从“说明页”变成真正的生产调度入口。
