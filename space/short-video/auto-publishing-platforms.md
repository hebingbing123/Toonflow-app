# 短视频 Space 自动发布平台方案

## 为什么这块值得补

Openflow 现在已经覆盖“生成前”和“生成中”的大部分链路，但从用户结果来看，还差最后一环：

- 生成好了
- 导出了
- 还要手动去各个平台逐个发布

如果补上“可选自动发布”，短视频 Space 就不只是生产台，还会变成一个更完整的分发台。这会成为和纯生成工具相比很明显的特色。

## 产品定位

不是强制自动发布，而是：

- 支持手动导出
- 支持手动发布准备
- 支持可选自动发布
- 支持定时发布
- 支持多平台分发

也就是说，自动发布应是 `export` 之后的一段独立流程，而不是直接塞进生成任务里。

## 平台分层建议

### 第一层：优先支持“有明显业务价值且可运营”的平台

国内：

- 抖音
- 哔哩哔哩
- 小红书
- 视频号
- 快手

海外：

- TikTok
- YouTube Shorts
- Instagram Reels
- Facebook Reels

### 第二层：按接入难度区分

优先做：

- 有开放 API 或较稳定发布接入方式的平台
- 支持视频上传、标题、简介、标签、封面、发布时间的基础发布模型

后做：

- 接口权限要求高、审核链长、企业资质限制强的平台
- 强依赖人工二次确认的平台

## Openflow 里的推荐产品结构

### 1. 发布目标配置

项目级维护：

- 目标市场：国内 / 海外 / 双端
- 默认平台集合
- 默认标题风格
- 默认标签策略
- 默认简介模板
- 默认发布时间策略

### 2. 成片发布单

每条待发布视频生成一张 `publish draft`：

- 来源项目
- 来源剧本/分镜/成片
- 视频文件
- 封面图
- 标题
- 简介
- 标签
- 平台差异化文案
- 发布时间
- 发布状态

### 3. 平台适配层

后端按平台做 adapter，负责：

- 字段映射
- 标题长度约束
- 标签规则
- 封面要求
- 视频比例/时长校验
- 发布时间格式
- 平台返回结果标准化

### 4. 发布任务中心

新增一类 `publish` 作业：

- queued
- validating
- uploading
- platform_processing
- succeeded
- partial_failed
- failed
- retrying

并能从任务直接回跳到对应发布单和项目。

## 最值得做的特色能力

### A. 一次生成，多平台改写

同一个成片自动生成多套：

- 国内口径标题
- 海外口径标题
- 平台定制标签
- 简介/描述

Agent 可以根据平台做轻改写，而不是用户自己手抄多遍。

### B. 发布前合规检查

在真正上传前先检查：

- 画幅是否符合 Shorts/Reels/竖屏要求
- 时长是否超限
- 标题是否超长
- 是否缺封面
- 是否缺标签
- 是否缺平台必填字段

### C. 定时与批量发布

支持：

- 立即发布
- 定时发布
- 同一成片多平台串行发布
- 同一项目按日历批量排程

### D. 发布结果回流

发布完成后把结果写回 Openflow：

- 平台视频 id
- 发布链接
- 发布时间
- 失败原因
- 重试记录

后续还能继续接：

- 播放量
- 点赞/评论
- 完播率
- 低表现预警

## 推荐实施顺序

### Wave 1：先把发布域模型立起来

- 项目级平台配置
- 发布单 `publish draft`
- 发布任务状态机
- 发布准备检查

### Wave 2：先接 2 到 3 个代表平台

建议优先从下面挑一组开始：

- 海外：YouTube Shorts、TikTok
- 国内：哔哩哔哩、抖音

我倾向先按这组做，因为它们最能覆盖“竖屏短视频 + 创作者工作流”的核心场景，且更容易验证产品价值。

### Wave 3：补平台差异化文案与排程

- 一键生成多平台标题/简介/标签
- 定时发布
- 批量排程

### Wave 4：补数据回流

- 平台链接回写
- 发布结果审计
- 基础表现数据同步

## 对 Openflow 架构的落点

后端建议新增一组独立发布域，而不是把发布逻辑混在现有生成任务里：

- `publish_profiles`
- `publish_drafts`
- `publish_targets`
- `publish_jobs`
- `publish_attempts`

前端短视频 Space 增加：

- 发布配置面板
- 发布准备检查
- 发布单列表
- 发布任务状态

## 需要提前注意的边界

- 平台 API 权限、审核与限流差异很大
- 不是所有平台都适合承诺“全自动”
- 有些平台更适合“自动准备 + 人工确认后发布”

所以产品文案和设计上更稳妥的说法应该是：

`支持多平台发布自动化，可按平台能力选择自动发布或半自动发布。`
