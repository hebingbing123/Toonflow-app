# Publish Copy Cache (J.1)

## Overview

The publish copy cache reduces redundant LLM calls by caching publish copy generation results based on input hash. When the same draft content and target platforms are requested again, the cached result is returned instead of making a new LLM call.

## Implementation

### Database Schema

Table: `app_publish_copy_cache`

- `id`: UUID primary key
- `input_hash`: TEXT (unique) - SHA256 hash of input parameters
- `platform_copy_fragment`: JSONB - Generated platform copy
- `source`: TEXT - Generation source ('llm', 'fallback', or 'cache')
- `created_at`: TIMESTAMPTZ - When the cache entry was created
- `last_used_at`: TIMESTAMPTZ - Last time this cache entry was used
- `use_count`: INTEGER - Number of times this cached result has been used

### Hash Computation

The input hash is computed from:
- Draft title
- Draft description
- Draft tags (sorted for stability)
- Target platform IDs (sorted for stability)
- Style hint (if provided)

The hash is stable across different orderings of tags and platforms, ensuring cache hits for equivalent inputs.

### Cache Flow

1. **Cache Lookup**: Before generating copy, compute input hash and check cache
2. **Cache Hit**: If found, update `last_used_at` and `use_count`, return cached result
3. **Cache Miss**: Generate copy via LLM or fallback, store result in cache
4. **Response**: Return copy with source indicator ('cache', 'llm', or 'fallback')

### API Response

The `SuggestPlatformCopyResponse` includes a `source` field that indicates:
- `"cache"`: Result was retrieved from cache
- `"llm"`: Result was freshly generated by LLM
- `"fallback"`: Result was generated by fallback template (no LLM available)

## Benefits

1. **Cost Reduction**: Eliminates redundant LLM calls for identical inputs
2. **Performance**: Cached results return instantly without LLM latency
3. **Consistency**: Same inputs always produce same outputs
4. **Metrics**: `use_count` tracks cache effectiveness

## Cache Invalidation

Currently, the cache has no automatic expiration. Future enhancements could include:
- TTL-based expiration
- Manual cache clearing per project
- Cache size limits with LRU eviction
- Platform spec version tracking

## Testing

Unit tests verify:
- Hash stability across different input orderings
- Hash uniqueness for different content
- Cache lookup and storage operations
